# ことばレンズ

ブラウザだけで動く日本語テキストマイニングツールです。

| ページ | 使う人 | 内容 |
| --- | --- | --- |
| `index.html` | だれでも | 文章を貼り付けて、その場で解析する（サーバー不要） |
| `teacher.html` | 教員 | 問いを作り、子どもに配るURL・QRコードを発行。集まった回答をリアルタイムで可視化 |
| `student.html?q=…` | 子ども | 教員から配られたURLを開き、ログインなし・匿名で回答を送る |

## 解析できること

- **頻出語**：出現回数・出現文書数・文字種の一覧（CSV をクリップボードにコピー可）
- **ワードクラウド**：出現回数を文字の大きさ、文字種を色で表示
- **共起ネットワーク**：同じ文・回答に現れる語を Jaccard 係数で結び、まとまりを色分け
- **連続する語**：2語の並び（バイグラム）の頻度
- **KWIC**：語が使われている前後の文脈を一覧表示

表やグラフの語をクリックすると KWIC に移動します。教員画面の「大きく表示」を押すと、問いと解析結果だけを大きく表示します（プロジェクター向け）。

## 授業での流れ

1. 教員が `teacher.html` に Google アカウントでログインし、問い（例：「今日の授業で心に残ったこと」）を作る
2. 表示された URL か QR コードを子どもに配る
3. 子どもはタブレットで開いて回答を書き、「送る」を押す（名前やアカウントは不要）
4. 教員画面の回答一覧と解析結果が自動で更新される。不適切な回答は「消す」で外せる
5. 終わったら「締め切る」。子どもの画面には受付終了と表示され、それ以上は送れない

## 保存されるデータとセキュリティ

- 回答として保存するのは **本文と送信時刻だけ** です。名前・端末・アカウントの情報は保存しません。
- 回答を読めるのは、その問いを作った教員だけです。子どもは回答を追加することしかできず、他の人の回答は見えません。
- 問いを作れるのは、`firestore.rules` に登録したメールアドレスの教員だけです。
- 回答は1件1000字まで、受付中の問いにだけ送れます（`firestore.rules` で強制）。
- 子どもの回答にはログインを求めないため、URL を知っている人はだれでも回答を送れます。URL は授業の中だけで配ってください。

## 教員向け：はじめの設定（1回だけ）

無料の Firebase（Google のサービス）にデータを保存し、ページは GitHub Pages で公開します。所要時間は20〜30分ほどです。

### 1. Firebase プロジェクトを作る

1. <https://console.firebase.google.com/> を開き、「プロジェクトを作成」（名前は例：`kotoba-lens`。Google アナリティクスは不要）
2. 左のメニュー「構築」→ **Firestore Database** →「データベースを作成」
   - ロケーションは `asia-northeast1`（東京）を推奨。「本番環境モード」で開始
3. 「構築」→ **Authentication** →「始める」→「ログイン方法」で **Google** を有効にする

### 2. セキュリティルールを設定する

1. このフォルダの `firestore.rules` を開き、`'teacher@example.com'` を **自分（教員）の Google アカウントのメールアドレス** に書き換える
   - 複数の教員で使う場合は `['a@school.jp', 'b@school.jp']` のように並べる
2. Firebase コンソールの Firestore Database →「ルール」タブに、書き換えた内容をすべて貼り付けて「公開」

### 3. ウェブアプリの設定値を貼り付ける

1. Firebase コンソールの歯車 →「プロジェクトの設定」→「マイアプリ」で **ウェブ（`</>`）** を選んでアプリを登録（Hosting は不要）
2. 表示された `firebaseConfig` の値（`apiKey`、`authDomain`、`projectId` など）を、このフォルダの `firebase-config.js` に貼り付ける
   - この値はページに埋め込んで公開してよいものです（データの保護はセキュリティルールで行います）

### 4. GitHub Pages で公開する

1. 変更をコミットして GitHub に push する
2. GitHub のリポジトリ →「Settings」→「Pages」で、公開するブランチ（例：`main`）とフォルダ `/ (root)` を選んで保存
   - 無料プランでは、リポジトリが公開（Public）になっている必要があります
3. 数分後に次の URL で開けます
   - 教員：`https://<ユーザー名>.github.io/<リポジトリ名>/textmining/teacher.html`
   - このリポジトリなら `https://horisukecom-sketch.github.io/kensuke_takahashi/textmining/teacher.html`
4. Firebase コンソールの Authentication →「設定」→「承認済みドメイン」に `horisukecom-sketch.github.io` を追加する（これがないと Google ログインが失敗します）

### 5. 動作を確かめる

1. 教員ページを開いて Google でログインし、問いを1つ作る
2. 表示された URL を別の端末（またはシークレットウィンドウ）で開き、回答を送る
3. 教員ページの回答一覧と解析結果に、送った回答が出れば完了

### うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| 「firebase-config.js がまだ設定されていません」 | 手順3の値が貼り付けられ、push されているか |
| ログインできない（`auth/unauthorized-domain`） | 手順4-4 の承認済みドメイン |
| 「教員として登録されていません」 | `firestore.rules` のメールアドレスと、ルールを「公開」したか |
| 子どもが「送れませんでした」 | 問いが「受付中」になっているか |

## 解析の仕組みと注意

単語の分割にはブラウザ内蔵の `Intl.Segmenter`（日本語の単語分割）を使います。品詞は判定しないため、「ひらがなだけの語を除く」と「除外する語」の設定で助詞などを取り除きます。ひらがなの多い文章では「変わる」が「変」、「楽しい」が「楽」のように1字の漢字に分かれることがあります。気になる場合は解析条件で「1文字の漢字は残す」を外すか、除外する語に追加してください。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `lens.js` / `lens.css` | 解析エンジンと共通の見た目（3ページで共有） |
| `index.html` | 単体で使う解析ツール |
| `teacher.html` / `teacher.js` | 教員画面 |
| `student.html` | 子どもの回答画面 |
| `firebase-config.js` | Firebase の接続設定（教員が値を貼り付ける） |
| `firestore.rules` | データベースのアクセス制限 |
